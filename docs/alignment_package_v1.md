# VSLP Alignment Package V1

This interchange package transports an already frozen Final Alignment Contract V1. Export does not run MFA or change token times, identities, review decisions, or feature formulas. The embedded producer remains available during migration. Raw TextGrid is not an Acoustic Features input.

## Layout

The package root contains `package_manifest.json`, the existing `final_alignment_manifest.json`, `final_alignment_contract_trials.csv`, `final_alignment_canonical_words.csv`, `final_alignment_canonical_phones.csv`, the existing provider word/phone and diagnostic CSVs, `recording_status.csv`, and `provenance.json`. Other frozen final files, including corrections, review/QC tables and evidence, are copied in their existing relative locations. No parallel scientific trial/word/phone schema is created. Optional raw provider output is not required for import.

`package_manifest.json` requires `package_contract_version=VSLP_ALIGNMENT_PACKAGE_V1`, `package_id`, `created_at`, `producer_application`, `producer_version`, `alignment_engine`, `alignment_engine_version`, `backend_name`, `backend_version`, `acoustic_model`, `dictionary`, `configuration_hash`, `recording_count`, `aligned_count`, `finalized_count`, `failed_count`, `package_file_hashes`, and `final_alignment_contract_version=FINAL_ALIGNMENT_CONTRACT_V1`. File hashes cover every exported file except the package manifest itself. The manifest retains backend identity but the scientific tables remain provider independent.

`recording_status.csv` has one row per finalized `record_key` (the current `recording_id`): `source_filename`, `task_id`, `prompt_id`, `transcript_hash`, `source_file_sha256` when the original source file is available, `source_audio_content_sha256`, `raw_source_audio_content_sha256` when available, `analysis_wav_sha256`, `sample_rate`, `channels`, `sample_count`, `alignment_status`, `review_status`, and `finalization_status`. An explicitly excluded project recording does not require an alignment package row.

`source_audio_content_sha256` is the binding identity of the **aligned analysis waveform**. The single helper reads frames with libsndfile/SoundFile as `float64`, always in frame-major/channel-major order, and hashes ASCII `sample_rate:channels:sample_count` followed by contiguous little-endian IEEE `float64` sample bytes. PCM decoding is normalized by libsndfile to floating-point values; IEEE float WAV values are read as stored. No downmix, gain, resampling, or timing transform is applied. The header is not included. Thus PEAK timestamps and unrelated WAV metadata do not alter scientific identity; changes in rate, channel count, frame count, or decoded values do. `source_file_sha256` and `analysis_wav_sha256` retain full serialized-file provenance, but their change alone does not block import when decoded content matches.

New frozen Final Alignment manifests carry `source_audio_content_sha256_by_recording` alongside the prior full-file `source_audio_sha256_by_recording`. The embedded loader uses decoded content when that map exists. Legacy manifests are not upgraded implicitly. A full-file mismatch remains stale unless an independent original aligned WAV is available or an exact PEAK-only reconstruction reproduces the frozen SHA-256. The reconstruction is limited to the time between project creation and alignment completion, at most one hour, and changes only the four PEAK timestamp bytes. A successful SHA-256 match proves the original serialized WAV and therefore its decoded samples; absent that proof, the legacy alignment remains stale. No content hash is written back to legacy artifacts.

`provenance.json` records the source alignment run ID, source final-segmentation decision and interval hashes, and the source Final Alignment manifest hash. The canonical tables retain their existing `trial_id`, `sequence_id`, `task_id`, prompt identity, original-time `start_sec`/`end_sec`, canonical word/phone IDs and indices, parent-word identity, boundary source, and final review status. Repeated trials remain separate.

## Export, import, and precedence

Export calls the existing `load_final_alignment()` first. A stale or unresolved embedded alignment cannot be exported as finalized. It copies frozen final files byte for byte, adds package identity metadata, and hashes the package. It does not recompute alignment.

Import validates version and required fields, every package-file hash, unique record keys and canonical identities, final review status, task/prompt identity, finite trial and token bounds, word-in-trial and phone-in-parent-word containment, current segmentation-review hashes, and current decoded audio-content hashes. Full-file hashes remain in the package for provenance. Validation uses a half-working-sample tolerance for containment, matching the existing Final Alignment loader; it does not round or alter serialized times. A successful explicit import is installed under `alignment_imports/<package_id>/` and recorded in `alignment_imports/active.json`.

When that explicit selection exists, `load_final_alignment()` returns the imported package through the same `AlignmentStore` interface. An invalid selected package yields an error; it never silently falls back to embedded files. Without an explicit selection, the existing embedded loader remains authoritative. Feature families continue to consume canonical Final Alignment through their current loader calls.

## Validation status and migration boundary

Synthetic package round-trip and negative-import tests exercise the interchange path. In the four-recording Bamboo run dated 2026-10-14, both rewritten analysis WAVs passed exact PEAK-only legacy SHA-256 reconstruction. The embedded loader then accepted all four records. The exported package imported into a separate project without an embedded Final Alignment; trial, word, phone, diagnostic, and original-time boundary tables matched exactly. Representative F4, F7, and F13 Bamboo feature values and statuses matched exactly for all four recordings. F5 and F6 have no applicable Bamboo task outputs. Embedded MFA and the Alignment Review widget remain in place. Standalone GUI extraction and cache changes are outside this pass.
