# Acoustic Pipeline: known limitations at release audit

This is a software status record, not a clinical validation statement. See the [release audit](acoustic_pipeline_release_audit.md) and [definition closure](acoustic_feature_final_definition_closure.md) for counts and exact IDs.

- **Intentionally unavailable source measures:** all eight Family 03 laryngeal-biomechanical constructs have no unique reproducible public ID; the Aural Analytics articulatory-precision leaf is proprietary. The other exact unavailable leaves are enumerated and individually classified in the [inventory](acoustic_feature_implementation_inventory.csv). None is selectable.
- **Unresolved templates:** 19 identities across Families 04, 05, 06, 07, 12 and 13 need approved target, acoustic landmark, source transform or parameter configuration. No placeholder becomes a selectable feature.
- **Task content:** The lab-supplied Bamboo Passage is registered as `bamboo_passage_v1` and resolves automatically for task-first Alignment. WSTG has only `wstg_we_see_three_geese` v1 (“We see three geese.”); the remaining stimulus inventory is unknown. Sustained phonation and DDK do not require linguistic MFA Alignment.
- **Bamboo rate numerator:** The canonical text has 97 whitespace tokens; Alignment's existing hyphen-splitting normalization produces 98 transcript words. Legacy configuration says 99 without an established source for that number. Family 08 still requires a separate approved versioned word/syllable-count manifest; no rate count was silently inferred.
- **MFA:** Unit and mocked integration tests exercise the provider. On this Windows PC, the opt-in cross-environment self-test and task-first WSTG engineering alignment passed through the installed external MFA environment. The separate real two-speaker corpus-to-feature test remains skipped because no approved nonclinical fixture/profile paths were supplied. A passing self-test demonstrates external-tool execution, not boundary accuracy or clinical validity.
- **Empirical validation:** Source-package parity, manually annotated boundary agreement, feature sensitivity to alignment error, ALS/clinical discrimination, longitudinal sensitivity and device robustness require separate reference data and protocols. Passing formula, synthetic and integration tests does not establish these properties.
- **Release data hygiene:** After explicit approval, 77 current files and one historical path alias were removed from the active index and all advertised remote branch/tag histories. A fresh clone verifies their absence from reachable history. Private local backups remain outside the repository; external clones and service caches are not covered by that verification. See the [data-hygiene audit](acoustic_data_hygiene_audit.md).
- **GUI workflow:** “Run to Manual Review” stops at the human review gate; “Continue after Review” opens Alignment only when selected outputs require it. Approved prompt counts, vowel categories, segmental targets and acoustic sub-event annotations still require scientist-supplied files when relevant. The task-first Alignment path needs no engineering manifest browsing in its normal view.
